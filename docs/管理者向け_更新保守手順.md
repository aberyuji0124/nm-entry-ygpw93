# 管理者向け　更新・保守手順

専門知識がなくても、ブラウザの操作だけで保守できるようにまとめています。

## 1. 仕組み（これだけ覚えれば大丈夫）

```
公式サイト ──(毎朝6時に1回)──▶ GitHub が自動で取り込む ──▶ data/schedule.json
                                                              │
会員のスマホ ◀──── 画面（GitHub Pages で公開）◀───────────────┘
```

- 日程の更新は**毎日自動**です。普段、管理者がすることはありません。
- 会員の個人情報（プロフィール・参加ログ）は、各自のスマホの中だけにあります。管理者側には届きません。

## 2. 毎週・毎月の確認（1分）

1. 画面（アプリ）を開く。
2. 画面上部に赤い「最新情報を取得できませんでした」が出ていなければ、正常です。
3. 「設定」の一番下に「日程データの最終更新」があります。昨日か今日の日付ならOKです。

## 3. 「最新情報を取得できませんでした」が出たとき

GitHub から、失敗を知らせるメールが管理者に届きます（件名に「日程を更新する」「failed」）。

1. GitHub のリポジトリを開く → 上の「Actions」タブ。
2. 赤い × の実行をクリック → 「update」をクリック → 赤く表示された手順の文章を読む。
3. 原因の見分け方：

| 表示されている内容 | 原因 | 対処 |
|---|---|---|
| 一覧表の見出し…が見つかりません／取得できた件数が少なすぎます | 公式サイトの作りが変わった | 4 へ |
| 詳細ページの◯/◯件が読み取れません | 支部ページの作りが変わった | 4 へ |
| タイムアウト・接続エラー | 公式サイトの一時的な不調 | 翌日の自動実行を待つ。急ぐときは 5 の手動実行 |

4. 公式サイトの作りが変わったとき：
   `tools/fetch_schedule.py` の読み取り部分（`parse_list` と `parse_detail`）を直す必要があります。
   Claude Code に「Actions のエラー文章」を貼って、「この取り込みスクリプトを直して」と頼んでください。直した後は 5 の手動実行で確認します。

※ 失敗しても、前回取り込んだ日程は残り、会員には「前回取得分を表示しています」と案内されます。

## 4. 手動で今すぐ更新する

1. GitHub のリポジトリ → 「Actions」タブ → 左の「日程を更新する」。
2. 右の「Run workflow」→ 緑の「Run workflow」。
3. 1〜10分で終わります（公式サイトに負荷をかけないよう、1件ずつ間隔をあけて取り込むため）。
4. 終わったら、アプリを開き直して反映を確認します。

※ 1日に何度も実行しないでください（公式サイトへの負荷を抑えるため）。

## 5. 公開の前に（重要）

- 本部の許可を得るまでは、URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）を**安部さん以外に伝えない**でください。
- このアプリには検索エンジンに載らない設定（noindex）を入れていますが、**URLを知っている人は誰でも開けます**。
- 許可が出たら、会員にURLを案内します。

## 6. 初回の公開手順（GitHub）

1. GitHub で新しいリポジトリを作る（Public。名前の例：`nm-entry`）。
2. このフォルダ（`app`）の中身を、リポジトリにアップロードする。
3. リポジトリの「Settings」→「Pages」→ Source を「Deploy from a branch」、Branch を「main」「/(root)」にして Save。
4. 数分後に、公開URLが表示される。
5. 「Settings」→「Actions」→「General」→ Workflow permissions を「Read and write permissions」にして Save。
6. 「Actions」タブ → 「日程を更新する」を手動実行して、日程が入ることを確認する。

## 7. 画面の更新をしたとき

画面（`app.js`・`style.css`・`index.html`）を直したら、`sw.js` の `VERSION = 'v1'` の数字を 1 つ増やしてください（`v2`、`v3`…）。会員のスマホに新しい画面が届きます。

## 8. 守ること

- 公式サイトへのアクセスは、1日1回・1件ずつ間隔をあけて行う設定です。変更しないでください。
- 主催・幹事などの個人名は、取り込まない作りです。
- 会員の個人情報を、管理者側で集めたり保管したりする仕組みは入れていません。
- 役員などの個人のメールアドレスは、取り込みません（メール申込の支部は、公式の支部ページを案内します）。
